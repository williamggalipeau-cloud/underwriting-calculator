# Sample deal documents (fictional, for testing)

Every document here is made up for testing the app: every page is marked
"SAMPLE – FICTIONAL – FOR TESTING ONLY", and the parties, addresses and
figures are invented, chosen to be consistent with Model Fund I's sample
assets and leases (`docs/sample-leases/`). Each phase that reads documents
adds its set here (plan decision 15).

## Everything ties out (1.1.13)

The fund and asset documents in `deals/` are written **from Model Fund I as
the app builds it**, so a document and the app never disagree:

1. `node scripts/sample-deal-docs/export_fund.cjs` writes
   `scripts/sample-deal-docs/fund.json` from `lib/sampleFund.js` (the function
   "Load Model Fund I" calls).
2. `python3 scripts/sample-deal-docs/deal_docs.py` reads every figure it
   shares with the app from `fund.json` (prices, units and rents, expenses,
   the loan and its lender, the cap, the marks, the IC figures). Only facts
   the app does not hold are written in the generator (contract dates and
   deposits, lender covenants and reporting, the cap's rating, the IC
   conditions, the LPA's limits).
3. `node scripts/sample-deal-docs/print_html.cjs docs/sample-deal-docs/deals [name …]`
   prints the PDFs.
4. `node scripts/sample-deal-docs/make_terms.cjs` reads each abstract into
   the fund with the app's own apply functions and writes
   `lib/sampleDocTerms.json`, which the sample fund then carries. It refuses
   if a document disagrees with the app or moves a loan, equity or return.
5. `node scripts/sample-deal-docs/copy_public.cjs` refreshes the copies the
   app uploads.
6. When a document is rewritten or retired, add its file name to
   `lib/sampleDocChanges.json` under the next `SAMPLE_DATA_VERSION`, so the
   automatic load replaces the earlier copy in a firm's data.

`tests/node/sampleTieOut.test.cjs` fails on any difference. Documents that
differ from the model on purpose (for the tests of comparing and applying a
document) live in `tests/fixtures/deal-docs` and are never loaded into the
app. **Not yet tied** (listed by that test): the nine leases, the estoppel,
tenant insurance certificate and CAM reconciliation that name their tenants,
the sale documents in `dispositions/`, and the `tenant-credit/` set below.

## Deal and fund documents (phase E) — `deals/`

Generated by `scripts/sample-deal-docs/deal_docs.py` (text and abstracts
together, so every quote is a sentence of the PDF) and printed with

The abstracts in `deals/abstracts/` pass the app's local check against the
PDF text. They are made for testing, not by the CREparser connector, so
they are marked "not connector-validated" even for types the connector can
